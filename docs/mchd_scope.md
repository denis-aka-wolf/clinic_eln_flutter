# Модуль МЧД для СФР

## Область действия

Модуль предназначен для управления машиночитаемыми доверенностями в процессах взаимодействия с Социальным фондом России (СФР), включая сценарии, связанные с медицинской организацией. Это не универсальный конструктор МЧД для ФНС или всех государственных органов: форматы, полномочия, статусы и способ регистрации зависят от системы-получателя.

Официальная страница СФР «Электронные доверенности (МЧД)» публикует XSD, спецификацию МЧД v2.0 и актуальный классификатор полномочий (на странице указан выпуск от 31.07.2026). Сервис СЭДО опубликован по адресу:

`https://ecp.sfr.gov.ru/sedo/soap/SedoGateway?wsdl`

Страница: <https://lk.sfr.gov.ru/mchd.html>

## Что реализовано в прототипе

- отдельный пункт навигации «МЧД»;
- локальный реестр с поиском по номеру, доверителю, представителю и коду полномочия;
- фильтры по черновикам, зарегистрированным, требующим внимания и отозванным доверенностям;
- создание и редактирование локального черновика;
- ввод реквизитов уже оформленной МЧД для внутреннего учёта со статусом «Требует проверки»;
- просмотр карточки доверенности;
- удаление только черновика;
- журнал локальных действий;
- контракт `SfrMchdGateway` и отдельный WSDL в конфигурации.

## Что намеренно не считается готовым

Все данные сейчас хранятся в памяти процесса и исчезают при завершении программы. Никакие операции не отправляются в СФР. Статусы в модели — внутренние статусы интерфейса, пока не получены реальные ответы и подтверждения СФР.

Не реализованы:

- загрузка актуального классификатора полномочий и выбор кодов из него;
- разбор XSD/XSD validation и формирование XML по спецификации СФР;
- подпись XML УКЭП доверителя и проверка сертификата/цепочки;
- передача МЧД и связанных служебных сообщений через СЭДО;
- получение подтверждения регистрации, отказа, текущего статуса и результата отзыва;
- импорт XML/P7S и проверка соответствия XML, подписи и записи в реестре;
- постоянное защищённое хранилище, разграничение доступа и полный аудит.

## Важное различие

МЧД представляет полномочия представителя действовать от имени доверителя в соответствующих процессах. Она не заменяет персональные подписи медицинского работника, которые спецификация ЭЛН требует для медицинских сведений. Поддержку МЧД надо связать с конкретными операциями МО по актуальным правилам СФР, не подменяя ею подпись врача или председателя врачебной комиссии.

## Рекомендуемый порядок дальнейшей реализации

1. Импортировать и проверить XSD и спецификацию МЧД v2.0, а также спецификацию СЭДО по МЧД из актуальной страницы СФР.
2. Добавить адаптер и модели сообщений СЭДО для классификатора полномочий, отправки/получения МЧД, получения статусов и отзыва. Контракт в `lib/data/sfr/sfr_mchd_gateway.dart` пока остаётся заглушкой.
3. Реализовать подписание и ГОСТ TLS через криптографический модуль Windows, не извлекая закрытые ключи в Flutter.
4. Пройти тестовый сценарий полного цикла: создать XML → подписать УКЭП доверителя → отправить → обработать квитанцию/статус → проверить регистрацию → инициировать отзыв и проверить его результат.
5. Добавить зашифрованное постоянное хранилище, роли пользователей, журнал аудита и уведомления об истечении доверенности.
