# Первичная карта спецификации ЭЛН МО 2.3

Источник анализа: материалы СФР из переданного архива, в частности «Спецификация ЭЛН МО v2.3», «Правила заполнения ЭЛН_Прод.xlsx», «ФЛК_ЭЛН.xlsx», инструкция по TLS ГОСТ и XSD сообщения 115. Это первичная карта требований, а не замена официальной спецификации и полного ФЛК.

## Состояния ЭЛН из спецификации

| Код | Смысл | Направление работы приложения |
|---|---|---|
| 010 | Открыт | Первичная выдача, основные данные пациента и МО, причина, диагноз, первый период и врач |
| 020 | Продлён | Новый период и сведения о враче, который продлевает |
| 030 | Закрыт | Дата приступить к работе либо результат «Иное» и связанная дата, если она предусмотрена |
| 040 | Направлен на МСЭ | Данные направления на МСЭ |
| 050 | Дополнен данными МСЭ | Даты/результаты МСЭ и предусмотренные моделью сведения |
| 060/070/080 | Последующие состояния страхователя | В основном чтение/отображение состояния и синхронизация, а не обычное заполнение МО |
| 090 | Действия прекращены/аннулирование | Отдельный разрешённый бизнес-сценарий и подтверждение пользователя |
| 091 | Извещение МО | Уведомление, для которого нужно обработать соответствующий формат сообщения СФР |

## Первичные проверки, которые уже есть в коде

- СНИЛС: 11 цифр и контрольное число.
- ОГРН/ОГРНИП: форма длиной 13/15 цифр (для окончательного ФЛК МО надо уточнить строгость по типу организации).
- Причина нетрудоспособности из базового набора кодов.
- Синтаксис кода МКБ-10.
- Обязательные ФИО, дата рождения, пол, реквизиты МО, врач, дата выдачи и хотя бы один период.
- Конец периода не раньше начала.
- Для продолжения указан номер предыдущего ЭЛН.
- Для причины ухода 09 проверены базовые поля лица, за которым осуществляется уход.
- Парность даты/кода нарушения режима и даты поступления/выписки.

## Правила, которые нужно перенести из полного ФЛК

1. Проверка СНИЛС, даты рождения и ФИО по данным СФР, когда соответствующая операция даёт такие сведения.
2. Сверка ОГРН и полномочий МО по реестру и сертификату.
3. Проверка того, что номер принадлежит МО/выдан СФР и допустим к изменению.
4. Проверки актуальности предшествующего состояния, периода и даты относительно ранее записанных данных.
5. Полное условное обязательное заполнение по статусам 010/020/030/040/050.
6. Проверка XML по актуальной XSD до подписания и отправки.
7. Справочники кодов причин, результатов закрытия, нарушений режима, родства, вида лечения и МСЭ.
8. Специальные бизнес-правила для беременности и родов, ухода, стационара, санаторного лечения, дубликатов и продолжений.
9. Проверка обязательного письменного согласия/признака, требуемого спецификацией, и корректное представление соответствующего значения в XML.
10. Проверка подписи ответа, обработки подписанных извещений и сообщений типа 115.

## Почему сейчас нельзя отправлять SOAP напрямую из Dart

В актуальном потоке требуется TLS 1.2 с ГОСТ-криптографией. Кроме транспортного TLS спецификация предусматривает подпись/шифрование XML-сообщений и проверку защищённого ответа. Поэтому `HttpClient` Dart сам по себе не является достаточной реализацией. В проекте оставлен интерфейс шлюза и безопасная заглушка до подключения Windows криптомоста и тестирования.

## Адрес

WSDL, опубликованный для медицинских организаций:

`https://eln.sfr.gov.ru/ws-mo-crypto/FileOperationsLnService?wsdl`

Окончательный SOAP endpoint, binding, namespaces, алгоритмы и XML-шаблоны следует извлекать из WSDL и проверять на тестовом контуре, а не закреплять на основании только URL страницы.
