# SQL Server и защищённая конфигурация

## Что использует приложение

- `dart_odbc: ^6.2.0` — прямое подключение через системный ODBC Driver Manager.
- `ODBC Driver 18 for SQL Server` — значение по умолчанию; драйвер должен быть установлен отдельно на компьютере пользователя.
- `dbo.ELN_AppData` — собственные записи приложения: JSON-пayload черновика ЭЛН или карточки МЧД, тип, идентификатор и локальный статус.
- `dbo.ELN_AuditLog` — технический журнал пользовательских действий без включения ФИО/СНИЛС пациента в описание события.

Приложение не читает, не обновляет и не меняет таблицы Медиалог. Выбирается именно база данных Медиалог, но для собственного хранения создаются только две таблицы с префиксом `ELN_`. Их создание требует отдельного подтверждения пользователя и соответствующих прав SQL Server.

## Первый запуск

1. Выбрать папку `BaseFiles`. Если выбрана другая родительская папка, приложение предложит структуру `<выбранная папка>/BaseFiles/ELN`.
2. Ввести сервер/экземпляр, порт, имя БД, имя ODBC-драйвера и вид авторизации.
3. Нажать **Проверить соединение**. Проверяется SQL-соединение и выполняется `SELECT DB_NAME(), SUSER_SNAME(), @@VERSION`; существующие данные не меняются.
4. Подтвердить создание `dbo.ELN_AppData` и `dbo.ELN_AuditLog`.
5. Параметры подключения сериализуются в памяти, шифруются AES-256-GCM и сохраняются в `BaseFiles/ELN/settings.<profile-id>.v1.enc`. У каждого Windows-профиля свой непрозрачный идентификатор файла и собственный ключ в защищённом хранилище ОС; общий каталог BaseFiles может содержать отдельные зашифрованные конфигурации рабочих мест.

## Защита

- В файловой системе не сохраняется открытый JSON конфигурации и не создаётся `.env`.
- `settings.<profile-id>.v1.enc` содержит только версию формата, nonce, ciphertext и authentication tag AES-GCM. Конфигурация старой версии в `settings.v1.enc` читается для перехода; при следующем сохранении создаётся профильный файл.
- Ключ AES, случайный ID профиля и путь к выбранному BaseFiles хранятся через `flutter_secure_storage` в защищённом хранилище ОС; в Windows используется интеграция с системным механизмом защищённого хранения. Это необходимо, чтобы найти файл и расшифровать его на следующем запуске.
- Если ключ отсутствует, существующий зашифрованный файл не должен молча перезаписываться новым ключом.
- Соединение с SQL Server по умолчанию шифруется (`Encrypt=Yes`), а проверка сертификата включена (`TrustServerCertificate=No`). Последний параметр можно отключить только осознанно, например во время настройки тестового сервера.
- Для production следует выдать приложению отдельный SQL-логин или Windows-пользователю только необходимые права на две `ELN_`-таблицы после их создания. Не используйте `sa` в пользовательском приложении.
- Встроенный UI — не граница безопасности для всей МИС. Нужны ACL на `BaseFiles`, индивидуальные права SQL Server, резервное копирование и аудит.

## Требования среды

- Flutter desktop (основной целевой вариант — Windows).
- Microsoft ODBC Driver 18 for SQL Server (либо явно выбранный совместимый установленный драйвер).
- Для Windows Integrated Authentication процесс Flutter должен запускаться от Windows-пользователя, которому выданы права на базу.
- Для сборки `flutter_secure_storage` под Windows могут потребоваться Visual Studio C++ Build Tools с компонентом ATL.

## Ограничения этапа

Сейчас сохранение черновиков ЭЛН и карточек МЧД, а также журнал локальных действий направлены в собственные SQL-таблицы. Это не означает, что интеграция с СФР уже работает: ГОСТ TLS, XML-подпись/шифрование, реальные SOAP-операции и подтверждения СФР реализуются отдельно.
