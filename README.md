# Клиника · ЭЛН

**Windows-ориентированное десктопное приложение на Flutter** для многопрофильной клиники. Текущая итерация добавляет зашифрованную конфигурацию `BaseFiles` и постоянное хранение записей ЭЛН и МЧД в SQL Server для собственных нужд приложения.

## Текущий функционал (Scope)

- Мастер первоначальной настройки запрашивает у пользователя корневую папку `BaseFiles` и параметры подключения к SQL Server для базы данных Медиалог.
- Поддерживается аутентификация в SQL Server по логину/паролю, а также сквозная проверка подлинности Windows (Windows Integrated Authentication).
- Используется пакет `dart_odbc: ^6.2.0` с параметризованным SQL и системным диспетчером драйверов ODBC.
- Соединение тестируется с помощью запроса только для чтения (`DB_NAME`, `SUSER_SNAME`, `@@VERSION`).
- После явного подтверждения приложение создает только таблицы `dbo.ELN_AppData` и `dbo.ELN_AuditLog`. Существующие таблицы Медиалога не изменяются.
- Черновики ЭЛН, записи МЧД и сообщения аудита приложения сохраняются в SQL Server.
- Конфигурация хранится в виде зашифрованного текста AES-256-GCM с аутентификацией по пути `BaseFiles/ELN/settings.<profile-id>.v1.enc`. Каждый профиль пользователя Windows получает уникальное непрозрачное имя файла, поэтому общая папка `BaseFiles` может содержать отдельные зашифрованные настройки для нескольких пользователей/рабочих станций. Ключ AES, идентификатор профиля и выбранный корневой путь сохраняются плагином `flutter_secure_storage` в защищенном хранилище операционной системы. Файлы настроек в виде открытого текста `.env` или JSON отсутствуют.
- По умолчанию используются драйвер SQL Server ODBC Driver 18, параметры `Encrypt=Yes` и `TrustServerCertificate=No`.
- Сетевой обмен ЭЛН СФР и СЭДО/МЧД отключен до тех пор, пока не будет реализован отдельно требуемый модуль ГОСТ TLS и подписания/шифрования XML.

## Важные ограничения (Boundaries)

Это приложение все еще находится на стадии разработки и не анализировалось и не компилировалось с помощью Flutter SDK в данной среде. Не вносите в него производственные данные пациентов до тех пор, пока оно не будет собрано, протестировано на контролируемой базе данных, проверено на безопасность и одобрено клиникой.

Приложение хранит свои собственные записи в выбранной базе данных Медиалог, в принадлежащих приложению таблицах с префиксом `ELN_`. Оно не читает и не изменяет собственные клинические таблицы Медиалога. Сохраняемые записи представляют собой JSON-структуры в SQL Server, а не зашифрованные локальные файлы. Разрешения базы данных, зашифрованный сетевой транспорт, резервное копирование на стороне сервера и требования к хранению данных должны быть настроены на уровне SQL Server.

Для первоначальной настройки понадобятся права на создание двух таблиц `ELN_`. Для повседневного использования администратор базы данных должен предоставить учетной записи приложения только те права, которые необходимы для этих двух таблиц. Не используйте учетную запись `sa`.

Файл `BaseFiles/ELN/settings.<profile-id>.v1.enc` защищен шифрованием AES-256-GCM. Его ключ, непрозрачный идентификатор профиля и выбранный корневой путь сохраняются в безопасном хранилище ОС, чтобы приложение могло найти и расшифровать файл при следующем запуске. Каждый профиль Windows имеет свой собственный зашифрованный файл настроек и ключ. Если профиль пользователя Windows или данные его безопасного хранилища будут утеряны, зашифрованный файл этого профиля невозможно будет расшифровать; поддерживайте утвержденную процедуру восстановления без экспорта ключа в открытый текст.

## Требования для Windows

1. Flutter SDK и поддержка сборки приложений для Windows Desktop.
2. Microsoft ODBC Driver 18 для SQL Server (или другой совместимый установленный драйвер, выбранный в настройках).
3. Учетная запись SQL Server с доступом к базе данных Медиалог.
4. Visual Studio C++ Build Tools с установленным компонентом ATL, если этого требует текущая реализация `flutter_secure_storage` под Windows.

При использовании сквозной аутентификации Windows (Windows Integrated Authentication) приложение должно запускаться от имени пользователя Windows, имеющего соответствующие разрешения в SQL Server. Для SQL-аутентификации используйте выделенный логин приложения, а не учетную запись системного администратора (sysadmin).

Выполните команды из корневой папки проекта (в PowerShell):

```powershell
flutter create --platforms=windows .
flutter pub get
flutter analyze
flutter test
flutter run -d windows
```

*Примечание: В текущей среде сборки живая база данных была недоступна, поэтому тесты подключения и сохранение данных в SQL еще не проверялись на реальном экземпляре Медиалога.*

## Сборка и развертывание (Deployment)

### 1. Компиляция релизной версии
Для генерации оптимизированного исполняемого файла выполните команду в PowerShell:

```powershell
flutter build windows --release
```
После завершения сборки все скомпилированные бинарные файлы, ресурсы и необходимые `.dll` зависимости плагинов (включая `dart_odbc` и `flutter_secure_storage`) будут находиться в каталоге:
`build\windows\x64\runner\Release\`

---

### 2. Варианты упаковки для развертывания на рабочих местах

Для автоматизированной установки приложения на компьютерах врачей выберите один из двух поддерживаемых методов упаковки.

#### Вариант А: Сборка пакета MSIX (Рекомендуется для Active Directory / Intune)
Формат `.msix` обеспечивает безопасную установку, автоматические обновления и чистое удаление без остаточных файлов.

1. Добавьте и настройте плагин `msix` в вашем `pubspec.yaml`:
   ```yaml
   dev_dependencies:
     msix: ^4.0.0
   ```
2. Настройте параметры сборки в конце `pubspec.yaml`:
   ```yaml
   msix_config:
     display_name: Клиника ЭЛН
     publisher_display_name: Наименование Клиники
     identity_name: com.clinic.eln.app
     publisher: 'CN=ClinicEnterpriseKit, O=Clinic, C=RU' # Должно совпадать с сертификатом
     logo_path: assets\icons\app_logo.png
     capabilities: internetClient # Доступ к сети для SQL Server
   ```
3. Выполните команду сборки (она автоматически скомпилирует релиз и упакует его):
   ```powershell
   flutter pub run msix:create
   ```
   *Готовый пакет `.msix` будет сохранен в папке `build\windows\x64\runner\Release\`.*

> ⚠️ **Важно:** Для развертывания пакета вне Microsoft Store (локально или через групповые политики Windows), файл `.msix` должен быть подписан доверенным сертификатом клиники (`.pfx`), а сам сертификат должен быть добавлен в хранилище «Доверенные корневые центры сертификации» на целевых компьютерах врачей.

#### Вариант Б: Создание классического установщика через Inno Setup
Подходит для стандартной установки в ручном режиме или через тихий запуск (`/VERYSILENT`).

1. Скачайте и установите [Inno Setup](https://jrsoftware.org).
2. Создайте файл конфигурации установки `installer_config.iss` в корне проекта со следующим содержимым:

```ini
[Setup]
AppName=Клиника ЭЛН
AppVersion=1.0.0
DefaultDirName={autopf}\ClinicELN
DefaultGroupName=Клиника ЭЛН
Compression=lzma2
SolidCompression=yes
OutputDir=build\windows\installer
OutputBaseFilename=ClinicELN_Setup
SetupIconFile=windows\runner\resources\app_icon.ico

[Files]
; Копируем исполняемый файл и абсолютно все сопутствующие файлы из папки сборки Flutter
Source: "build\windows\x64\runner\Release\*"; DestDir: "{app}"; Flags: ignoreversion recursesubdirs createallsubdirs

[Icons]
Name: "{group}\Клиника ЭЛН"; Filename: "{app}\клиника_элн.exe"
Name: "{autodesktop}\Клиника ЭЛН"; Filename: "{app}\клиника_элн.exe"; Tasks: desktopicon

[Tasks]
Name: "desktopicon"; Description: "Создать ярлык на рабочем столе"; Flags: unchecked

[Run]
Filename: "{app}\клиника_элн.exe"; Description: "Запустить Клиника ЭЛН"; Flags: nowait postinstall skipifsilent
```

3. Скомпилируйте установщик через интерфейс Inno Setup Compiler или из командной строки:
   ```powershell
   & "C:\Program Files (x86)\Inno Setup 6\ISCC.exe" installer_config.iss
   ```
   *Итоговый автономный файл `ClinicELN_Setup.exe` будет собран в папке `build\windows\installer\`.*

### 3. Автоматизированное развертывание в доменной архитектуре (SCCM / Intune / GPO)

Если в клинике развернута доменная инфраструктура, установку приложения на рабочие станции врачей можно полностью автоматизировать. Ниже приведены шаблоны PowerShell-скриптов для «тихой» (silent) установки обоих типов пакетов.

#### Сценарий А: Тихий импорт сертификата и установка пакета `.msix`
Для успешного развертывания `.msix` на компьютерах домена необходимо предварительно установить доверенный корневой сертификат клиники, которым подписан пакет, иначе Windows заблокирует установку.

```powershell
# Шаблон скрипта развертывания MSIX (Запускать от имени Администратора / SYSTEM)
$NetworkPath = "\\domain-storage\shares\ClinicELN" # Сетевая папка с дистрибутивом
$CertificateName = "ClinicEnterpriseKit.cer"
$MsixName = "ClinicELN.msix"

# 1. Импорт сертификата в доверенные корневые центры сертификации компьютера
Write-Output "Импорт сертификата безопасности..."
Import-Certificate -FilePath "$NetworkPath\$CertificateName" -CertStoreLocation "Cert:\LocalMachine\Root" -ErrorAction SilentlyContinue

# 2. Тихая установка пакета MSIX для всех пользователей компьютера
Write-Output "Установка пакета Клиника ЭЛН (.msix)..."
Add-AppxProvisionedPackage -Online -PackagePath "$NetworkPath\$MsixName" -SkipLicense -ErrorAction Stop

Write-Output "Развертывание MSIX успешно завершено."
```

#### Сценарий Б: Тихая установка классического инсталлятора .exe (Inno Setup)

Inno Setup из коробки поддерживает ключи автоматической установки. Флаг /VERYSILENT полностью скрывает интерфейс установщика, а /MERGETASKS="desktopicon" принудительно создает ярлык для всех пользователей.
```powershell

Шаблон скрипта развертывания EXE-установщика (Запускать от имени Администратора)

$NetworkPath = "\domain-storage\shares\ClinicELN"
$SetupExecutable = "ClinicELN_Setup.exe"
$LogPath = "C:\Windows\Temp\ClinicELN_Install.log"
Write-Output "Запуск тихой установки Клиника ЭЛН..."

Запуск процесса установки с ожиданием его завершения

$Arguments = "/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /MERGETASKS="desktopicon" /LOG="$LogPath""
$Process = Start-Process -FilePath "$NetworkPath$SetupExecutable" -ArgumentList $Arguments -Wait -NoNewWindow -PassThru
if ($Process.ExitCode -eq 0) {
Write-Output "Приложение успешно установлено. Лог сохранен в $LogPath"
} else {
Write-Error "Ошибка установки. Код возврата: $($Process.ExitCode). Проверьте лог: $LogPath"
}
```
💡 Рекомендация для системных администраторов клиники:
• При развертывании через Групповые политики (GPO): Скрипт для .msix рекомендуется назначать как Startup Script (Конфигурация компьютера), чтобы он выполнялся до входа пользователя в систему с правами NT AUTHORITY\SYSTEM.
• При использовании SCCM / Microsoft Intune: Скрипт для .exe можно обернуть в стандартный тип развертывания приложений (Windows app), указав в строке запуска параметры ClinicELN_Setup.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART.

Важные файлы проекта

• lib/core/security/base_files_config_store.dart — зашифрованный файл конфигурации + защищенный на уровне ОС ключ.
• lib/core/config/db_connection_settings.dart — настройки ODBC и построение строки подключения.
• lib/data/sqlserver/sql_server_data_store.dart — подключение к SQL Server, creation схемы данных и параметризованные операции.
• lib/data/sqlserver/sql_server_eln_repository.dart — постоянное хранение черновиков ЭЛН + строки аудита.
• lib/data/sqlserver/sql_server_mchd_repository.dart — постоянное хранение записей МЧД + строки аудита.
• lib/features/setup/initial_setup_screen.dart — мастер первоначальной настройки (wizard).
• sql/001_create_eln_app_tables.sql — доступная для проверки SQL-миграция, эквивалентная созданию таблиц при первом запуске приложения.
• docs/sql_storage.md — подробная информация о хранении данных, безопасности и развертывании.

Следующий этап работы по ЭЛН / СФР

Сохранение данных в SQL реализовано независимо от сетевого взаимодействия со спецификациями СФР. Следующим шагом станет интеграция криптографического шлюза под Windows для поддержки ГОСТ TLS 1.2, подписания/шифрования XML и валидации подписей. Затем предстоит маппинг официального SOAP-контракта ЭЛН (МО) и тестирование методов getNewLNNum / prParseFilelnlpu на тестовом контуре СФР. На текущий момент реальные запросы в ЭЛН не отправляются и не принимаются.
